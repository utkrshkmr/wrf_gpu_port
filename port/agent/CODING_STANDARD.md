# Coding standard for GPU kernels

This is the binding version of plan.md §7.0 and §8.0 for the agent. Every pattern here has a **tested** example
in the repository; copy from those, not from memory. `port/tools/arith_guard.py` and `port/tools/kernel_lint.py`
enforce most of the rules (run `bash port/gates/static.sh`).

Contents: 1 anatomy of a ported routine · 2 routes · 3 islands · 4 directives · 5 templates A, B, C, D, G, L, CP ·
6 variables · 7 reductions, errors, messages · 8 module data and calls · 9 what the CPU view may contain ·
10 per-routine checklist.

## 1. Anatomy of a ported routine

The complete, tested example is [`port/tests/tools/example_calc_alt.F`](../tests/tools/example_calc_alt.F)
(`calc_alt`, K-PREP-7). Differences from the CPU source, and nothing else:

```fortran
SUBROUTINE calc_alt ( alt, al, alb, ... )
   USE module_gpu_route, ONLY : gpu_on, gpu_island, gpu_world_host, R_CALC_ALT   ! (a) allowed in the CPU view
   IMPLICIT NONE
   ... declarations unchanged ...
#ifdef WRF_GPU
   LOGICAL :: gpu_isl                                                            ! (b) GPU view only
#endif
#ifdef WRF_GPU
      gpu_isl = gpu_island(R_CALC_ALT)                                           ! (c) entry island
      IF (gpu_isl) THEN ... !$omp target update ... gpu_world_host = .NOT. gpu_world_host ... END IF
#endif
      ... unchanged host code (scalars, bounds) ...
!$omp target teams distribute parallel do collapse(3) if(target: gpu_on(R_CALC_ALT)) default(none) &
!$omp& shared(alt, al, alb) firstprivate(its, itf, jts, jtf, kts, ktf)          ! (d) the kernel directive
      DO j=jts,jtf                                                               !     in front of the unchanged loop
      ...
#ifdef WRF_GPU
      IF (gpu_isl) THEN ... END IF                                               ! (e) exit island
#endif
END SUBROUTINE calc_alt
```

- (a), (c), (e) are generated by `python3 port/tools/gen_island.py <file> <routine>`.
- Directive lines are comments for CPU-REF (it is built without OpenMP), so (d) needs no `#ifdef`.
- A restructured kernel (templates B, C, L, CP) goes into an `#ifdef WRF_GPU` block that ends with the exit island
  and `RETURN`; the original loops stay below it for CPU-REF, untouched. Example:
  [`port/tests/tools/calc_coef_w_gpu.inc`](../tests/tools/calc_coef_w_gpu.inc) (inserted after
  `IF(top_lid)lid_flag=0` of `calc_coef_w`; see `test_agent_tools.py` for the exact insertion).

**Unported branches.** A routine often has branches the case never takes (other advection orders, periodic or
symmetric boundaries, other physics options). Do not port them. In the GPU view they must not run on the host after
the island moved the data: put, under `#ifdef WRF_GPU` and **before the entry island**, a test that stops the model,
e.g. `IF (horz_order /= 5 .OR. vert_order /= 3) CALL wrf_error_fatal('advect_u: order not ported to the GPU')`.
`gpu_check_config` rejects those options at startup; this is the second safety net.

## 2. Routes

Every kernel carries `if(target: gpu_on(R_<ROUTE>))`. The route list is fixed in
`WRF/frame/module_gpu_route.F` (101 routes, one per routine of plan.md §7–§10; `KERNEL_REFS.md` and `kernels.csv`
give the route of each kernel). A routine that plan.md groups under another route (e.g. `horizontal_diffusion_u_2`
under `horizontal_diffusion_2`, `add_a2a` under `update_phy_ten`) uses that route. Adding a route: append the
name to `route_name`, add `R_<NAME>`, raise `nroutes` (module_gpu_route.F is port infrastructure and may be edited).

`WRF_GPU_OFF=name1,name2` / `WRF_GPU_ONLY=...` switch routes at run time (T-AB). With a route off, the same
GPU-view code runs on the host (`if(target: .false.)` runs the construct on the host), over host data.

## 3. Islands (data residency)

`module_gpu_route` keeps one flag, `gpu_world_host`: `.TRUE.` while the current values of the model arrays are in
host memory. Through Phase 4 the model stays on the host (the whole-`solve_em` bracket of P1.9) and each ported
routine moves **its own array arguments** in its island; Phase 5 (P5.3) flips the world to the device, and then only
switched-off routes move data. The same island code serves every phase:

- entry: `gpu_isl = gpu_island(R_X)` is `.TRUE.` when the routine runs where the data are not (host world and route
  on, or device world and route off). Then every array dummy (all intents) is copied to where the routine runs, and
  the world flag flips while the routine runs (so the islands of routes nested inside see the right world);
- exit: flip back, copy every non-`INTENT(IN)` array dummy back.

How the whole-state copies fit in (Phases 1–4, PHASE1.md step "P1.5 + P1.9"): the bracket downloads the state at the
top of `solve_em` and uploads it at the end; between steps the sync points upload what host code changes (initial
state, nest start, boundary read, nest forcing) and download before host code reads (nest start, history, restart,
nest forcing). So between two `solve_em` calls host and device copies are equal, and inside `solve_em` the host copy
is the current one — which is why the flag stays `.TRUE.` through Phase 4 and islands only move data for routes that
are on. Never remove or reorder one half of this (an upload without its download or the reverse): the model then
silently continues from stale data.

Rules:

1. Generate the island with `gen_island.py`; do not write it by hand. Put the entry block at the first executable
   statement (after early `RETURN`s that do no work, e.g. `IF (.NOT. something) RETURN` at the top), and the exit
   block before **every** `RETURN` after the entry and before `END SUBROUTINE`. The tool lists the lines.
2. An array the routine reads or writes that is **not a dummy argument** (a module array changed at run time, a
   `grid%` component used by a callee) must be added to the island by hand. Module tables that never change after
   init are uploaded once by P1.4 and need nothing.
3. A dummy of `TYPE(domain)` (`grid`) is moved with the generated whole-state updates `gpu_upd_dev_all(grid)` /
   `gpu_upd_host_all(grid)` (P1.3). This is correct but slow; use it only for driver routines.
4. `OPTIONAL` array dummies are moved under `IF (PRESENT(x))`; assumed-size dummies (`x(*)`) cannot be moved by name
   (the tool warns): move the actual argument in the caller instead.
5. `kernel_lint` rule E9 requires an island for every route that has a kernel in the file. If the island of a route
   is in another routine (a driver that moves the data for several callees), write the comment
   `! island of R_<ROUTE> in <routine>` next to the kernel.
6. Islands only move data that is already mapped: state arrays (P1.2), pool arrays (P1.6), work arrays (P1.7),
   tables (P1.4). An array that is not mapped (a caller's automatic array) is silently not moved by `target update`
   and silently copied by every kernel that uses it. Every large automatic array reaching a kernel must become a work
   array (P1.7); `T-NSYS` shows the copies.

## 4. Directives

The default kernel directive, for every kernel:

```fortran
!$omp target teams distribute parallel do collapse(N) if(target: gpu_on(R_X)) default(none) &
!$omp& shared(<arrays>) firstprivate(<scalars read>) private(<scalars and fixed-size arrays written>)
```

- A comment with the kernel ID directly above the directive (at most 3 lines above), e.g.
  `! K-ADVU-Y1: face fluxes (Template B)`. `kernel_off.py` finds kernels by this ID (DEBUGGING.md §2).
- `default(none)` always: every variable must be listed; the compiler then tells you what you forgot.
- `collapse(N)`: N perfectly nested `DO` loops follow (no statement between them). `N=3` for (j,k,i) pointwise,
  `N=2` for (j,i) columns and 2D fields.
- Keep the loop order of the source (j outer, k, i inner); inner index i is the fastest for memory.
- No `map(to|from|tofrom:...)` clauses: data is resident (kernel_lint E3). `map(present, alloc: ...)` and
  `defaultmap(present: aggregate)` are allowed; use `defaultmap(present: aggregate) defaultmap(present: allocatable)`
  on every kernel if probe F-DEFMAP passed on the H100 (H0.3) — it turns a forgotten mapping into a run-time error.
- `teams loop` only for kernels without calls and only if probe F-CALLS showed no difference; the safe default is
  `teams distribute parallel do` (kernel_lint W1 warns on `teams loop` with calls).
- `reduction(max: x)`, `reduction(+: n)` for scalar results (§7).
- Continuation: end the line with `&`, start the next with `!$omp&`. **Never an apostrophe (`'`) in a directive
  line**: WRF's build deletes comment lines containing one before the preprocessor runs.
- Loop bounds must be scalars known before the kernel (copy `MIN(ite,ide-1)` etc. into locals first, as the source
  does). Non-rectangular nests (bounds of an inner loop that depend on the outer index) cannot be collapsed:
  collapse only the rectangular outer loops.

## 5. Templates

| Template | When | Tested example |
|---|---|---|
| **A** pointwise | every iteration independent; the loop writes only its own (i,k,j) | `port/tests/tools/example_calc_alt.F` |
| **B** rolling buffer → two kernels | a j-loop carries fluxes from iteration j to j+1 (`fqy(:,:,jp1/jp0)`) | `port/tests/templates/t_tmpl_b.F90` (`advect_u` y-flux: K-ADVU-Y1/Y2) |
| **C** column | a vertical recurrence, or per-j slabs (`dmdt(its:ite)`, `divv(its:ite,kts:kte)`) | `port/tests/templates/t_tmpl_c.F90` (`calc_ww_cp`), `port/tests/tools/calc_coef_w_gpu.inc` (`calc_coef_w`) |
| **D** calls | the loop body calls a procedure | §8 |
| **G** boundary strips | copies into halo/boundary rows | `port/tests/templates/t_tmpl_g.F90` (`set_physical_bc3d`) |
| **L** split update | an iteration updates neighbours (limiter) | `port/tests/pdlim/t_pdlim.F90` (K-PD-L3a/b) |
| **R** row-parallel | the source shares state across i within a j-row (`ozn_p_int`'s `kkstart`) | `port/tests/ozn/t_ozn.F90` (K-OZP) |
| **CP** column physics | a physics wrapper loops over j slabs and calls a column scheme | plan.md §8.0; §5.7 below |

### 5.1 Template A — pointwise

Put the directive in front of the loop; change nothing in the loop. Loops that write the same array element from
two iterations, or read an element another iteration writes, are **not** pointwise: use B, C, G, L or R.

When the source has several loop nests one after the other, each becomes its own kernel, in source order (kernel
boundaries keep the ordering). Do not fuse them (fusion is optimization O7, Phase 6, and must not reorder anything).

### 5.2 Template B — rolling buffer

Source pattern (advect_u y-flux, `KERNEL_REFS.md` row K-ADVU-Y1): for `j = j_start, j_end+1`: compute face fluxes of
row j into `fqy(:,:,jp1)` (with a branch chosen by j), then for `j > j_start` update the tendency of row j-1 from
`fqy(jp1) - fqy(jp0)`, then swap jp1/jp0. Port:

- Y1: one kernel over (j,k,i), `j = j_start .. j_end+1`, computing the same face flux into a 3D work array
  `fqy3(i,k,j)` with **the same branch for the same j** and the same expressions;
- Y2: one kernel over (j,k,i), `j = j_start+1 .. j_end+1`, `tendency(i,k,j-1) = tendency(i,k,j-1) -
  mrdy*(fqy3(i,k,j)-fqy3(i,k,j-1))` with `mrdy` private and computed exactly as in the source.

The x-flux of the same routines has no rolling buffer (fqx(i) and fqx(i+1) of the same row): either compute both
faces per thread (the flux of a face is then computed twice, by the two neighbouring threads, with identical
expressions, which is exact), or X1/X2 like Y1/Y2. The z-flux is a column (template C) with `vflux(kts)` and
`vflux(kte)` set inside the kernel.

### 5.3 Template C — column

One thread per (i,j) column: `collapse(2)` over j, i; the k loops run sequentially inside, in the source order and
direction.

- A per-j slab `s(its:ite, kts:kte)` becomes a private fixed-size column `s_col(WRF_KMAX+1)` (never a
  runtime-sized private array; `WRF_KMAX` = 64, checked at startup by `gpu_check_config`).
- A per-j vector `v(its:ite)` becomes a private scalar.
- Initializations done once before the j loop (`rhs(:,1)=0`) move into the column (same value each time).
- **Range guards:** statement groups of one source j-iteration often run over different i ranges (`calc_ww_cp`:
  zeroing over `its..ite`, the recurrence over `its..itf`; `advance_uv`: `i_start_u_tend` vs `i_start_up`). The
  kernel runs i over the union and each group keeps its own range: `IF (i >= lo .AND. i <= hi) THEN ... END IF`.
- Sums over k (`dmdt = dmdt + divv(k)`) stay sequential in the source order.

### 5.4 Template D — kernels that call procedures

- Use `teams distribute parallel do`.
- The callee and everything it calls get `!$omp declare target` (as the first line after the procedure's
  declarations part begins — directly after the `SUBROUTINE`/`FUNCTION` statement line is the usual place).
- Scalars the callee reads from its module (constants, tables) must be `declare target` data uploaded by P1.4.
- The callee must not do I/O, allocate, call `wrf_error_fatal` or use `grid%`/`config_flags%` (return an error code
  instead; §7).
- Statement functions (`flux5`, WSM6's `cpmcal`, ...) may stay if probe F-STMTFN passed (and `ref_tests.sh` printed
  no NOTE about them). Otherwise convert each to a `PURE` **module** function (not an internal one: F-INTPROC)
  with the identical expression and `!$omp declare target`, and pass as arguments the host variables the statement
  function used (e.g. `time_step` in `flux3`/`flux5`). The worked example is the `TMPL_NO_STMTFN` form of
  `port/tests/templates/t_tmpl_b.F90`.

### 5.5 Template G — boundary strips

Each strip loop nest of the source gets its own kernel, in source order; x strips before y strips (the y strips read
the corners the x strips wrote). The host logic that chooses the branch (`open_xs`, `specified`, variable letter,
tile position) stays unchanged host code. Never merge strips of different phases into one kernel.

### 5.6 Templates L and R

L (limiter): see plan.md §7.5 K-PD-L3a/b and `t_pdlim.F90`: a per-cell flag and scale, then per-face kernels applying
the donor-cell rule. R (row-parallel): keep the source's i loop sequential inside one thread per j when the source
shares a search state across i (`ozn_p_int`); per-j arrays become work arrays with a j index.

### 5.7 Template CP — column physics (Phase 3)

plan.md §8.0 CP-1..CP-5 is binding. In short: one kernel over (j,i) replaces the wrapper's j loop; each thread copies
its column into private fixed-size arrays with the wrapper's own expressions, calls the core routine with
`its=ite=1, kts=1, kte=nz`, and copies the results back with the wrapper's expressions. The core routine and its
callees are `declare target`; every automatic array sized by the tile becomes fixed-size (`WRF_KMAX`,
`WRF_NLAYMAX`); whole-array syntax on those arrays (`a(:) = 0.`, `SIZE(a)`) must be rewritten to the active
extent `a(1:nz)`. The original wrapper stays for CPU-REF (`#ifndef WRF_GPU`). Details and the per-scheme list are
in PHASE3.md.

## 6. Variables

| In the source | In the kernel |
|---|---|
| scalar computed inside the loop | `private` |
| scalar set before the loop and read inside | `firstprivate` (never `shared` for scalars) |
| `config_flags%x` used inside a loop | copy to a local scalar before the kernel; `firstprivate` |
| `grid%x` inside a loop | not allowed in a kernel (kernel_lint E5): pass the array as an argument or use the dummy |
| module parameter (`PARAMETER`) | nothing (constant) |
| module variable (table, species index `P_QV`) | `declare target` + upload in P1.4, or copy to a local scalar |
| automatic array of the routine | work array (P1.7) if it is large or crosses kernels; private fixed-size array if per column |
| array element passed to a callee as an array (`a(1,k)`) | pass an explicit section of the private/work array |

## 7. Reductions, errors and messages

- Max/min/sum of scalars over the kernel: `reduction(max: x)` etc. Integer sums are exact; a floating-point sum
  reduction is **not** allowed unless the result only feeds messages (its order differs from the host).
- A `WRITE`, `wrf_message`, `wrf_debug` or `wrf_error_fatal` inside a loop: replace with an integer counter or flag
  (`reduction(+: nbad)` / `reduction(max: ierr)`); after the kernel, on the host, if the flag is set, do what the
  source did (print the same message; for messages that need the offending values, rerun the loop on the host to
  find them; for fatal errors call `wrf_error_fatal` with the same text).
- `STOP` in device code: replace with an error code as above.

## 8. Module data and calls

- Tables read in kernels (`module_sf_noahlsm` parameters, WSM6 SAVE scalars, RRTMG `rrlw_kg*`, sfclayrev psi tables,
  fire flags) are `!$omp declare target(...)` in their module and uploaded once by `gpu_update_tables()` (P1.4).
- The `P_*` species indices of `module_state_description` are integer variables, not parameters: copy the ones a
  kernel needs into local scalars (`firstprivate`), or `declare target` them.
- A callee that is also called from host code keeps working on the host (`declare target` builds both versions).

## 9. What the CPU view may contain

With `WRF_GPU` undefined, a file must compile to the CPU-view base statement for statement. Allowed additions
(arith_guard): `USE module_gpu_*`/`module_bittrace`/`omp_lib`/`iso_c_binding`; `CALL gpu_*`, `CALL bt_*`,
`CALL wrf_nvtx_*`; `#include "gpu_*"`/`"island_*"`; `IF (gpu_on(R_X)) THEN` / `IF (.NOT. gpu_on(R_X)) THEN` blocks
and their `END IF`; directive lines. Everything else goes under `#ifdef WRF_GPU`. Port infrastructure files
(`WRF/frame|share|phys/module_gpu_*.F`, `module_bittrace.F`) are not compared.

## 10. Per-routine checklist

- [ ] CPU lines read with `ref.py <kernel id>` (base commit); the whole routine read once, in `ref.py <routine>` pages;
- [ ] template chosen; kernels in source order; statements copied verbatim;
- [ ] every kernel: route, `default(none)`, complete data-sharing lists, correct `collapse`, no map, no I/O;
- [ ] island generated and placed (entry after early returns; exit before every later RETURN and the END);
- [ ] unported branches stop with `wrf_error_fatal` in the GPU view, before the entry island;
- [ ] non-dummy arrays the routine touches handled (island or P1.4 table);
- [ ] error branches and messages converted (§7);
- [ ] `static.sh` PASS; build shows the kernels offloaded (`-Minfo=mp`);
- [ ] `harness.sh <file> <routine>` PASS (HOST vs DEVICE, CPU vs DEVICE) for each code path you ported (`--set`);
- [ ] `t_ab.sh <route> W-20` and `t_trace.sh W-20` PASS;
- [ ] every kernel has its `! K-...` ID comment; no `KOFF-TEMP` edit left (static.sh checks);
- [ ] kernels.csv and the workbook updated; commit names kernel IDs and tests.
